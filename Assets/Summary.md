# 3D 큐브 체스 프로젝트 진행 요약 (Summary)

## 🎯 오늘 진행한 주요 작업 목표
6개의 면이 존재하는 정육면체(큐브) 형태의 체스 판 위에서, 체스 판을 자유롭게 회전시키고 체스 말을 직관적으로 조작할 수 있는 기초 시스템을 구축했습니다.

---

## 🛠️ 구현된 주요 시스템 및 스크립트

### 1. `BoardRotator.cs` (체스 판 회전 및 줌 제어)
* **트랙볼 회전 (Trackball Rotation):** 
  * 마우스 우클릭 상태로 드래그 시, 카메라 시점 기준의 상하좌우 축을 계산하여 체스 판이 직관적으로 회전하도록 구현.
  * 회전 보간(`Quaternion.Slerp`)을 적용하여 프레임 드랍이나 마우스의 빠른 이동에도 화면이 끊기지 않고 쫀득하고 부드럽게 돌아가도록 최적화.
* **마우스 휠 줌 (Zoom In/Out):**
  * 마우스 스크롤 휠을 굴려 정육면체의 스케일(Scale)을 직접 제어하여 확대 및 축소를 구현.
  * 인스펙터에서 줌 속도와 한계치(`minScale`, `maxScale`)를 자유롭게 설정할 수 있도록 제작.

### 2. `ChessPieceController.cs` (체스 말 로컬 좌표 기반 조작)
* **물리 연산 배제 (No Rigidbody):** 
  * 보드가 회전할 때 물리 연산으로 인해 말이 미끄러지거나 떨리는 현상을 원천 차단하기 위해 유니티 물리 엔진(Rigidbody)을 제거.
  * 체스 말을 보드의 완벽한 자식(Child)으로 편입시킴.
* **로컬 좌표 변환 레이캐스트 (Local Space Raycasting):**
  * 큐브가 어떤 각도로 돌아가 있더라도, 마우스가 가리키는 월드 좌표를 큐브의 '로컬 좌표계'로 변환(`InverseTransformPoint`)하여 연산.
  * 덕분에 대각선으로 보드가 누워있는 상태에서도 좌표계 왜곡 없이 완벽한 연산이 가능해짐.
* **오차율 0%의 수학적 그리드 스냅 (Mathematical Grid Snapping):**
  * 유저가 에디터에서 직접 측정한 정확한 한 칸의 크기(`0.48`)와 보드 가장자리 한계값(`±1.68`) 데이터를 코드에 직접 대입.
  * 마우스가 어느 곳을 가리키든 해당 위치에서 가장 가까운 체스판 격자의 정중앙 좌표로 체스 말을 툭툭 강제 보정(Snap) 시키는 수식 적용.
* **들고 놓기 & 호버링 (Pick-up, Drop & Hovering):**
  * 좌클릭을 눌러 말을 잡으면 붕 뜨고(`hoverHeight`), 놓으면 제자리로 부드럽게 스르륵 착지(`dropSpeed`).
  * 잡고 있는 동안 큐브의 어떤 면으로 넘어가더라도, 해당 면의 법선(Normal)을 받아 즉각적으로 수직 방향으로 똑바로 섬.
  * 잡고 있을 때 레이캐스트가 자기 자신을 맞추는 오류를 방지하기 위해 콜라이더 자동 On/Off 기법 적용.

### 3. 호버 인디케이터 (Hover Indicator)
* 말을 들고 이동할 때, 현재 마우스가 가리키는 바닥 칸의 색상을 변하게 해주는 시각적 하이라이트 기능 추가.
* 텍스처와 겹쳐서 깜빡이는 현상(Z-fighting)을 방지하기 위해 표면에서 아주 미세하게(0.01f) 띄우는 디테일 적용.

## 📅 [2026-05-16 ~ 05-17] 핸드 트래킹(Hand Tracking) 연동 및 조작감/비주얼 고도화

### 1. Python MediaPipe 제스처 인식 고도화 (`hand_tracking.py`)
* **좌우 손 판별 구조 개선:** MediaPipe의 고질적인 라벨 오류를 무시하고, 거울 모드(화면 상의 X 좌표) 및 해부학적 구조를 기준으로 왼손과 오른손을 직관적으로 강제 배정.
* **손가락 곡률 비율 (Finger Curl Ratio) 적용:** `(손가락 끝-손목 거리) / (손가락 밑동-손목 거리)` 비율을 구하는 현업 표준(VR/AR 기기) 공식을 도입. 카메라와의 거리나 손목 회전에 무관하게 "손가락이 접혔음"을 완벽하게 판별.
* **우선순위 상태 머신 (Prioritized State Machine) 적용:** 
  * "네 손가락이 접혔는가?"를 최우선으로 검사하여 **주먹(Fist)**을 확정하고, 그 외의 경우에만 **핀치(Pinch)**를 평가하도록 설계. 
  * 주먹을 쥘 때 엄지가 검지에 닿아 핀치로 오작동하는 고질적인 버그 원천 차단.

### 2. Unity 조작감 극대화 (`HandVisualizer.cs`)
* **디바운스(Debounce) 타이머 적용:** 파이썬에서 날아오는 1프레임 단위의 오류(노이즈)를 무시하고, 포즈가 `0.15초` 이상 안정적으로 유지될 때만 애니메이션과 상태를 변경하도록 필터링.
* **가상 바운딩 박스 (가시 영역 증폭):** 유저의 팔 피로도를 줄이기 위해, 화면 중앙의 작은 공간만 휙휙 움직여도 모니터 전체 영역을 커버할 수 있도록 X/Y 이동 민감도 증폭.
* **동적 스무딩 (Dynamic Smoothing):** 레이저가 멀리 갈 때는 빠르게(Fast), 가까운 거리를 미세 조정할 때는 무겁게(Slow) 움직이도록 설계하여 수전증(에임 떨림) 완벽 억제.

### 3. 체스 기물 시각 피드백 추가 (`ChessPieceController.cs`)
* **동적 외곽선 쉐이더 (`SimpleOutline.shader`):** 에셋 다운로드 없이, 스크립트에서 동적으로 메쉬를 복사하고 자체 제작한 쉐이더를 씌워 얇고 예쁜 청록색 외곽선 구현. (거대화 스케일 버그 대응을 위해 두께 파라미터 분리)
* **스케일 피드백:** 레이저를 올리거나(Hover) 핀치로 집어들면(Grab) 기물의 크기가 1.3배로 부드럽게 커지며, 놓으면 원상복구되는 쫀득한 피드백 추가.
* **마우스/핸드 트래킹 스위칭:** `Use Hand Tracking` 체크박스를 추가하여 언제든지 기존의 마우스 조작 방식(레이캐스트 & 클릭)으로 넘나들 수 있도록 백업 로직 보존.

## 📅 [2026-05-18] 3D 턴제 이동 시스템 및 BFS 적군 AI 구현

### 1. 면 횡단 위상 매핑 및 그리드 시스템 (`GridManager.cs`)
* **3D 큐브 전개도 기반 위상 매핑(Topology):** 큐브의 6개 면을 8x8 그리드로 논리적으로 분할하고, 기물이 모서리(Edge)를 넘을 때 인접한 면으로 부드럽게 넘어갈 수 있도록 좌표와 축을 자동 변환해주는 `GetNeighbor` 로직을 구축.
* **`GridPos` 구조체 도입:** 면(Face), X, Y 좌표를 묶어 3D 공간 상의 모든 타일을 고유하게 식별 및 추적하는 논리 좌표계 완성.

### 2. 플레이어 턴(전술 게임형) 확정 시스템 (`ChessPieceController.cs`)
* **이동 번복(자유 배치) 허용:** 기물을 내려놓아도 즉시 턴이 넘어가지 않고, 턴을 시작한 최초 좌표(`turnStartGridPos`)를 기억하여 플레이어 턴 내내 자유롭게 경로를 수정하며 미리 배치해 볼 수 있도록 설계.
* **이동 확정 (Commit Move):** UI의 `END` 버튼을 눌러야만 비로소 이동이 확정되고 적 턴으로 넘어가게 하는 정통 전술형 턴 기반 플로우 구현.
* **경로 시각화 (Path Visualizer):** 유효한 이동 경로(면 횡단 포함)에만 1칸 크기의 패널을 깔아주어 이동 가능한 영역을 직관적으로 제시.

### 3. 적 폰 추적 AI: BFS 플로우 필드 구현 (`GameManager.cs`)
* **거리 맵핑 알고리즘:** A* 대신 전체 보드에 최적화된 BFS(너비 우선 탐색)를 도입. 플레이어 위치를 0으로 두고 전체 384칸의 보드 거리를 단 한 번의 탐색으로 맵핑(Flow Field).
* **벌떼(Swarm) 추적 움직임:** 각 폰들이 인접한 칸들 중 가장 숫자가 적은(플레이어와 가까운) 타일로 1칸씩 전진하게 하여, 연산량이 극히 적으면서도 자연스러운 포위망 구축 완성.
* **매끄러운 이동 애니메이션 (DOTween):** 
  * 같은 면 안에서는 큐브 표면을 부드럽게 미끄러지며(Slide) 이동(`DOLocalMove`).
  * 모서리를 꺾어 넘을 때는 폴리곤 안으로 파고들지 않게 아주 살짝만 튀어 오르는(Hop) 점프 처리(`DOLocalJump`).
  * 애니메이션과 유니티 기본 `Update`(Lerp) 루프가 서로 충돌해 앞뒤로 덜덜 떨리던(Jittering) 버그를 상태 잠금(Animation Lock)으로 완벽 해결.
